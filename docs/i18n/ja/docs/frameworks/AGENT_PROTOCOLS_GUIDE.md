> **最終更新:** 2026-06-28 — v3.8.40

OmniRoute は、エージェントに関連する3つの異なるインターフェースを提供します。一見似ていますが、それぞれ異なる問題を解決します。このページを参考に、適切なものを選択してください。

## 要約

| インターフェース                     | 最適な用途                                                                                                                                   | トランスポート                      | 標準                     |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- | ------------------------ |
| **A2A — エージェント間連携**         | A2A プロトコルに対応するピアエージェントとの、エージェントをまたぐコラボレーション                                                           | HTTP 上の JSON-RPC 2.0              | A2A v0.3（オープン仕様） |
| **ACP — CLI エージェントレジストリ** | ユーザーのマシンにインストールされている CLI コーディングエージェント（Cursor、Cline、Codex CLI、Claude Code、Aider など）の検出、登録、起動 | HTTP REST                           | OmniRoute 固有           |
| **クラウドエージェント**             | 外部クラウドサービス（Codex Cloud、Devin、Jules、Cursor Cloud）への長時間実行されるコーディングタスクの送信                                  | HTTP REST + DB バックエンドのタスク | OmniRoute 固有           |

これら3つは独立しています。必要なものを自由に組み合わせて選択してください。

## 判断フロー

## 1. A2A — エージェント間連携

**仕様:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute エンドポイント:** `POST /a2a`（JSON-RPC 2.0）
**エージェントカード:** `GET /.well-known/agent.json`

### 使用する場面

- OmniRoute がピアの1つとなるマルチエージェントシステムを構築する場合
- OmniRoute のルーティング機能（スマートルーティング、クォータ管理など）を、Google ADK のようなフレームワークや汎用エージェントメッシュ内のエージェントに公開する場合
- OmniRoute を標準の検出および呼び出しインターフェースでラップする場合

### メソッド

- `message/send` — メッセージを送信し、同期レスポンスを受信
- `message/stream` — メッセージを送信し、SSE ストリーミングによる進捗イベントを受信
- `tasks/get` — ID を指定してタスクを取得
- `tasks/cancel` — 実行中のタスクをキャンセル

### 組み込みスキル（6種類）

- `smart-routing` — 最適な組み合わせを通じてプロンプトをルーティング
- `quota-management` — プロバイダーごとのクォータ状態を報告
- `provider-discovery` — インストール済みプロバイダーとその機能を一覧表示
- `cost-analysis` — リクエストまたは会話のコストを見積もり
- `health-report` — プロバイダーごとのブレーカー、クールダウン、ロックアウト状態を集約
- `list-capabilities` — エージェントで利用可能なスキルとメタデータを列挙

### 詳細

トランスポートの詳細、エージェントカードの構造、タスクの TTL 設定、新しいスキルを追加するためのテンプレートについては、[A2A-SERVER.md](./A2A-SERVER.md)を参照してください。

## 2. ACP — CLIエージェントレジストリ

**OmniRouteエンドポイント:** `GET /api/acp/agents`
**ソース:** `src/lib/acp/{index,manager,registry}.ts`

### 概要

ACPはOmniRouteの**ローカルCLIエージェントインベントリ**です。ホストにインストールされているコーディングCLI（Cursor、Cline、Claude Code、Codex CLI、Continueなど）を検出し、そのバージョンを特定してダッシュボードに表示します。これにより、ユーザーは各CLIの接続先をOmniRouteに設定できます。

HTTPインターフェースは、「CLI Tools」UIとCLIフィンガープリント追跡を支える内部インベントリです（[CLI-TOOLS.md](../reference/CLI-TOOLS.md)を参照）。これとは別に、内部プロセスマネージャーは、登録済みのGeminiランチャー向けのネイティブAgent Client Protocolと、その他のコントラクト向けの従来のstdioアダプターをサポートします。これらの異なるモードと制限については、[ACPレジストリとランチャー](./ACP.md)を参照してください。

### 機能

- インストール済みのCLIバイナリをホスト上で検索します（OSに応じて`which` / `where`を使用）
- 各CLIのバージョンを取得します（`<bin> --version`を呼び出し）
- 必要に応じて、ユーザー定義のカスタムエージェントを受け付けます（バイナリパス、バージョン確認、起動引数）
- カスタムエージェントを設定に永続化します
- 統合された一覧をダッシュボードに返します

### REST API

| エンドポイント    | メソッド | 説明                                                                        | 認証    |
| ----------------- | -------- | --------------------------------------------------------------------------- | ------- |
| `/api/acp/agents` | GET      | 検出済みエージェントとカスタムエージェントの一覧（インストール済み数/総数） | APIキー |
| `/api/acp/agents` | POST     | カスタムエージェントの追加/更新/削除（本文内のaction判別子）                | APIキー |

POSTの本文形式（`src/app/api/acp/agents/route.ts`内の`customAgentBodySchema`）:

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### ユースケース

- ダッシュボードの「CLI Tools」ページにインストール済みのツールを一覧表示し、各ツールの接続先をOmniRouteに設定できるよう支援します
- カスタムエージェントにより、上級ユーザーは、OmniRouteがデフォルトでは認識しない社内用/プロプライエタリなCLIを登録できます
- 検出結果は`cli-tools`フィンガープリントマトリックスに使用されます

### ACPを使用すべきでない場合

- HTTPレジストリはタスクを受け付けず、プロセス起動機能も公開しません。内部マネージャーは登録済みCLIを起動できますが、自動的なプロバイダーのフォールバックとしては接続されていません。通常の対話的な使用では、設定済みのCLIを自分で起動するか、`omniroute run`を使用してください。

## 統合例

### OmniRoute の A2A 機能を検出する

```bash
curl http://localhost:20128/.well-known/agent.json
```

6 つのスキル、トランスポート、バージョンをすべて含む Agent Card を返します。

### OmniRoute を A2A エージェントとして呼び出す

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### ACP 経由でインストール済みの CLI エージェントを一覧表示する

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### カスタム CLI エージェントを追加する

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## 用途別の使い分け

- **チャットボット / コパイロットのフロントエンド** → `/v1/chat/completions`（OpenAI 互換 — エージェントプロトコルではない）
- **マルチエージェント連携** → A2A
- **ダッシュボードでのローカル CLI の一覧表示** → ACP
- **長時間実行されるコーディングタスクのクラウドサービスへの委任** → Cloud Agents

```
                │   OmniRoute コア    │

    │  A2A  │        │   ACP   │       │ クラウド   │

   外部ピア            CLIバイナリ               ↓
   エージェント                           Codex Cloud、Cursor、
                                          Devin、Jules
```
