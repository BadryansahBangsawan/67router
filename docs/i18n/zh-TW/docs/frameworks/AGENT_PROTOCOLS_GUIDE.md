67router 提供三種不同的代理程式相關介面。乍看之下它們很相似，但解決的是不同問題。請使用本頁選擇適合的介面。

## 簡要說明

| 介面                         | 最適合的用途                                                                                                 | 傳輸方式                     | 標準                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------- | -------------------- |
| **A2A — 代理程式對代理程式** | 與支援 A2A 協定的對等代理程式進行跨代理程式協作                                                              | 透過 HTTP 的 JSON-RPC 2.0    | A2A v0.3（開放規範） |
| **ACP — CLI 代理程式登錄庫** | 偵測／註冊／啟動安裝於使用者電腦上的 CLI 程式設計代理程式（Cursor、Cline、Codex CLI、Claude Code、Aider 等） | HTTP REST                    | 67router 專用        |
| **雲端代理程式**             | 將長時間執行的程式設計任務提交至外部雲端服務（Codex Cloud、Devin、Jules、Cursor Cloud）                      | HTTP REST + 資料庫支援的任務 | 67router 專用        |

三者彼此獨立——可任選其中任意組合。

## 決策樹

## 2. ACP — CLI 代理程式登錄檔

**67router 端點：** `GET /api/acp/agents`
**原始碼：** `src/lib/acp/{index,manager,registry}.ts`

### 這是什麼

ACP 是 67router 的**本機 CLI 代理程式清單**。它會偵測主機上安裝了哪些程式設計 CLI（Cursor、Cline、Claude Code、Codex CLI、Continue 等）、解析其版本，並將這些資訊顯示於儀表板，讓使用者可將每個 CLI 設定為指向 67router。

此 HTTP 介面是內部清單，為「CLI 工具」UI 和
CLI 指紋追蹤提供支援（請參閱 [CLI-TOOLS.md](../reference/CLI-TOOLS.md)）。此外，
內部程序管理器支援已登錄 Gemini 啟動器的原生 Agent Client Protocol，以及其他合約的
舊版 stdio 轉接器。
如需瞭解這些不同模式及其限制，請參閱 [ACP 登錄檔與啟動器](./ACP.md)。

### 功能

- 探查主機上已安裝的 CLI 二進位檔（依作業系統使用 `which` / `where`）
- 讀取每個 CLI 的版本（呼叫 `<bin> --version`）
- 可選擇接受使用者定義的自訂代理程式（二進位檔路徑 + 版本探查 + 啟動引數）
- 將自訂代理程式持久儲存於設定中
- 將整合後的清單傳回儀表板

### REST API

| 端點              | 方法 | 說明                                                       | 驗證     |
| ----------------- | ---- | ---------------------------------------------------------- | -------- |
| `/api/acp/agents` | GET  | 列出偵測到的代理程式與自訂代理程式（已安裝／總數）         | API 金鑰 |
| `/api/acp/agents` | POST | 新增／更新／移除自訂代理程式（動作識別欄位位於請求本文中） | API 金鑰 |

POST 的本文格式（`src/app/api/acp/agents/route.ts` 中的 `customAgentBodySchema`）：

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### 使用案例

- 儀表板的「CLI 工具」頁面會列出已安裝的工具，並協助您將每個工具指向 67router
- 自訂代理程式可讓進階使用者登錄 67router 預設不認識的內部／專有 CLI
- 偵測結果會提供給 `cli-tools` 指紋矩陣使用

### 不應使用 ACP 的情況

- HTTP 登錄檔不接受工作，也不提供程序啟動功能。內部
  管理器可以啟動已登錄的 CLI，但未連接為自動提供者
  備援。若是一般互動式使用，請自行啟動已設定的 CLI，或
  使用 `omniroute run`。

## 整合範例

### 透過 ACP 列出已安裝的 CLI 代理程式

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### 新增自訂 CLI 代理程式

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## 使用時機

- **聊天機器人／copilot 前端** → `/v1/chat/completions`（OpenAI 相容——並非代理協定）
- **多代理協作** → A2A
- **在儀表板中列出本機 CLI** → ACP
- **將長時間執行的程式設計任務委派給雲端服務** → Cloud Agents
