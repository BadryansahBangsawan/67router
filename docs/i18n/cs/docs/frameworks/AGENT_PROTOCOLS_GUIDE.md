> **Poslední aktualizace:** 2026-06-28 — v3.8.40

OmniRoute nabízí tři různá rozhraní související s agenty. Na první pohled vypadají podobně, ale řeší odlišné problémy. Tato stránka vám pomůže vybrat to správné.

## Stručně

| Rozhraní                     | Nejvhodnější použití                                                                                                                                      | Transport                      | Standard                        |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ | ------------------------------- |
| **A2A — Agent-to-Agent**     | Spolupráce mezi agenty s partnerskými agenty, kteří používají protokol A2A                                                                                | JSON-RPC 2.0 přes HTTP         | A2A v0.3 (otevřená specifikace) |
| **ACP — registr CLI agentů** | Zjišťování / registrace / spouštění CLI agentů pro programování nainstalovaných na počítači uživatele (Cursor, Cline, Codex CLI, Claude Code, Aider atd.) | HTTP REST                      | Specifické pro OmniRoute        |
| **Cloudoví agenti**          | Zadávání dlouhotrvajících programovacích úloh externím cloudovým službám (Codex Cloud, Devin, Jules, Cursor Cloud)                                        | HTTP REST + úlohy uložené v DB | Specifické pro OmniRoute        |

Všechna tři rozhraní jsou nezávislá — můžete si vybrat libovolnou podmnožinu.

## Rozhodovací strom

## 1. A2A — Agent-to-Agent

**Specifikace:** [A2A v0.3](https://a2a-protocol.org)
**Koncový bod OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**Karta agenta:** `GET /.well-known/agent.json`

### Kdy použít

- Při vytváření systému s více agenty, ve kterém je OmniRoute jedním z partnerských agentů
- Při zpřístupnění směrovací inteligence OmniRoute (inteligentní směrování, správa kvót atd.) agentům ve frameworkách, jako je Google ADK, nebo v obecných sítích agentů
- Při zapouzdření OmniRoute za standardním rozhraním pro zjišťování a vyvolávání

### Metody

- `message/send` — odešle zprávu a přijme synchronní odpověď
- `message/stream` — odešle zprávu a přijímá události průběhu streamované přes SSE
- `tasks/get` — načte úlohu podle ID
- `tasks/cancel` — zruší spuštěnou úlohu

### Vestavěné dovednosti (6)

- `smart-routing` — směruje prompt přes optimální kombinaci
- `quota-management` — hlásí stav kvót jednotlivých poskytovatelů
- `provider-discovery` — vypíše nainstalované poskytovatele a jejich možnosti
- `cost-analysis` — odhadne náklady na požadavek nebo konverzaci
- `health-report` — agreguje stav jističe, doby vychladnutí a uzamčení pro jednotlivé poskytovatele
- `list-capabilities` — vypíše dostupné dovednosti agenta a metadata

### Podrobnosti

Podrobnosti o transportu, struktuře karty agenta, konfiguraci TTL úloh a šabloně pro přidávání nových dovedností najdete v dokumentu [A2A-SERVER.md](./A2A-SERVER.md).

## 2. ACP — Registr CLI agentů

**Endpoint OmniRoute:** `GET /api/acp/agents`
**Zdroj:** `src/lib/acp/{index,manager,registry}.ts`

### Co to je

ACP je **lokální inventář CLI agentů** v OmniRoute. Zjišťuje, která vývojářská CLI jsou na hostiteli nainstalována (Cursor, Cline, Claude Code, Codex CLI, Continue atd.), určuje jejich verze a zpřístupňuje je v řídicím panelu, aby uživatel mohl každé CLI nastavit tak, aby používalo OmniRoute.

HTTP rozhraní představuje interní inventář, který zajišťuje fungování uživatelského rozhraní „CLI Tools“ a
sledování otisků CLI (viz [CLI-TOOLS.md](../reference/CLI-TOOLS.md)). Interní
správce procesů samostatně podporuje nativní Agent Client Protocol pro
registrovaný spouštěč Gemini a starší adaptéry stdio pro jiné kontrakty.
Informace o těchto odlišných režimech a omezeních najdete v dokumentu [Registr ACP a spouštěče](./ACP.md).

### Co dělá

- Vyhledává na hostiteli nainstalované binární soubory CLI (podle operačního systému používá `which` / `where`)
- Zjišťuje verzi každého CLI (volá `<bin> --version`)
- Volitelně přijímá vlastní agenty definované uživatelem (cesta k binárnímu souboru + příkaz pro zjištění verze + argumenty spuštění)
- Ukládá vlastní agenty do nastavení
- Vrací sjednocený seznam do řídicího panelu

### REST API

| Endpoint          | Metoda | Popis                                                               | Ověření  |
| ----------------- | ------ | ------------------------------------------------------------------- | -------- |
| `/api/acp/agents` | GET    | Vypíše zjištěné + vlastní agenty (počty nainstalovaných/celkem)     | Klíč API |
| `/api/acp/agents` | POST   | Přidá/aktualizuje/odebere vlastního agenta (rozlišovač akce v těle) | Klíč API |

Struktura těla požadavku POST (`customAgentBodySchema` v `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Případy použití

- Stránka „CLI Tools“ v řídicím panelu zobrazuje, co je nainstalováno, a pomáhá nastavit jednotlivé nástroje tak, aby používaly OmniRoute
- Vlastní agenti umožňují pokročilým uživatelům registrovat interní/proprietární CLI, která OmniRoute ve výchozím nastavení nezná
- Výsledek detekce slouží jako podklad pro matici otisků `cli-tools`

### Kdy ACP NEPOUŽÍVAT

- Registr HTTP nepřijímá úlohy ani nezpřístupňuje spouštění procesů. Interní
  správce může spustit registrované CLI, ale není zapojen jako automatický záložní
  poskytovatel. Pro běžné interaktivní použití spusťte nakonfigurované CLI sami nebo
  použijte `omniroute run`.

## Příklady integrace

### Zjištění možností A2A systému OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

Vrátí kartu agenta se všemi 6 dovednostmi, transporty a verzí.

### Volání OmniRoute jako agenta A2A

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Výpis nainstalovaných CLI agentů prostřednictvím ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Přidání vlastního CLI agenta

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## Kdy co použít

- **Frontend chatbota / kopilota** → `/v1/chat/completions` (kompatibilní s OpenAI — nejde o protokol agenta)
- **Spolupráce více agentů** → A2A
- **Výpis místních CLI v řídicím panelu** → ACP
- **Delegování dlouhotrvajících programátorských úloh cloudovým službám** → cloudoví agenti

