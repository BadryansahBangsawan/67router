67router tilbyder tre forskellige agentrelaterede grænseflader. De ligner hinanden ved første øjekast, men løser forskellige problemer. Brug denne side til at vælge den rigtige.

## Kort fortalt

| Grænseflade                         | Bedst egnet til                                                                                                                                        | Transport                       | Standard              |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------- | --------------------- |
| **A2A — agent-til-agent**           | Samarbejde på tværs af agenter med peer-agenter, der understøtter A2A-protokollen                                                                      | JSON-RPC 2.0 over HTTP          | A2A v0.3 (åben spec.) |
| **ACP — register over CLI-agenter** | Registrering, detektering og start af CLI-kodningsagenter, der er installeret på brugerens maskine (Cursor, Cline, Codex CLI, Claude Code, Aider osv.) | HTTP REST                       | 67router-specifik     |
| **Cloud-agenter**                   | Indsendelse af langvarige kodningsopgaver til eksterne cloudtjenester (Codex Cloud, Devin, Jules, Cursor Cloud)                                        | HTTP REST + DB-baserede opgaver | 67router-specifik     |

De tre er uafhængige — vælg en hvilken som helst kombination.

## Beslutningstræ

## 2. ACP — register over CLI-agenter

**67router-slutpunkt:** `GET /api/acp/agents`
**Kilde:** `src/lib/acp/{index,manager,registry}.ts`

### Hvad det er

ACP er 67routers **lokale oversigt over CLI-agenter**. Det registrerer, hvilke kodnings-CLI'er der er installeret på værten (Cursor, Cline, Claude Code, Codex CLI, Continue osv.), finder deres versioner og viser dem i kontrolpanelet, så brugeren kan konfigurere hver CLI til at pege på 67router.

HTTP-grænsefladen er en intern oversigt, som driver brugergrænsefladen "CLI Tools" og
sporing af CLI-fingeraftryk (se [CLI-TOOLS.md](../reference/CLI-TOOLS.md)). Separat
understøtter den interne procesadministrator den oprindelige Agent Client Protocol for den
registrerede Gemini-starter samt ældre stdio-adaptere til andre kontrakter.
Se [ACP-register og startere](./ACP.md) for oplysninger om disse separate tilstande og begrænsninger.

### Hvad det gør

- Undersøger værten for installerede CLI-binærfiler (bruger `which` / `where` afhængigt af operativsystemet)
- Læser versionen for hver CLI (kalder `<bin> --version`)
- Accepterer valgfrit brugerdefinerede agenter (sti til binærfil + versionskontrol + startargumenter)
- Gemmer brugerdefinerede agenter i indstillingerne
- Returnerer den samlede liste til kontrolpanelet

### REST-API

| Slutpunkt         | Metode | Beskrivelse                                                          | Godkendelse |
| ----------------- | ------ | -------------------------------------------------------------------- | ----------- |
| `/api/acp/agents` | GET    | Vis registrerede + brugerdefinerede agenter (installeret/antal)      | API-nøgle   |
| `/api/acp/agents` | POST   | Tilføj/opdater/fjern brugerdefineret agent (handling angivet i body) | API-nøgle   |

Body-format for POST (`customAgentBodySchema` i `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Anvendelsestilfælde

- Siden "CLI Tools" i kontrolpanelet viser, hvad der er installeret, og hjælper dig med at konfigurere hvert værktøj til at pege på 67router
- Brugerdefinerede agenter giver superbrugere mulighed for at registrere interne/proprietære CLI'er, som 67router ikke kender som standard
- Registreringsresultatet bruges som datagrundlag for fingeraftryksmatricen `cli-tools`

### Hvornår ACP IKKE skal bruges

- HTTP-registeret accepterer ikke opgaver og tilbyder ikke start af processer. Den interne
  administrator kan starte en registreret CLI, men er ikke forbundet som en automatisk
  reserveudbyder. Ved almindelig interaktiv brug skal du selv starte den konfigurerede CLI eller
  bruge `omniroute run`.

## Integrationseksempler

### Vis installerede CLI-agenter via ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Tilføj en brugerdefineret CLI-agent

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## Hvornår du skal bruge hvad

- **Chatbot-/copilot-frontend** → `/v1/chat/completions` (OpenAI-kompatibel — ikke en agentprotokol)
- **Samarbejde mellem flere agenter** → A2A
- **Visning af lokale CLI'er i dashboardet** → ACP
- **Uddelegering af langvarige kodningsopgaver til cloudtjenester** → Cloud Agents
