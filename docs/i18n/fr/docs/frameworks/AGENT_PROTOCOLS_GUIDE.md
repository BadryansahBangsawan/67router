OmniRoute expose trois interfaces différentes liées aux agents. Elles semblent similaires à première vue, mais répondent à des besoins différents. Utilisez cette page pour choisir celle qui convient.

## En bref

| Interface                       | Idéale pour                                                                                                                                                          | Transport                          | Standard                         |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | -------------------------------- |
| **A2A — Agent à agent**         | La collaboration entre agents avec des agents pairs prenant en charge le protocole A2A                                                                               | JSON-RPC 2.0 sur HTTP              | A2A v0.3 (spécification ouverte) |
| **ACP — Registre d’agents CLI** | La détection, l’enregistrement et le lancement d’agents de codage CLI installés sur la machine de l’utilisateur (Cursor, Cline, Codex CLI, Claude Code, Aider, etc.) | HTTP REST                          | Spécifique à OmniRoute           |
| **Agents cloud**                | La soumission de tâches de codage de longue durée à des services cloud externes (Codex Cloud, Devin, Jules, Cursor Cloud)                                            | HTTP REST + tâches stockées en BDD | Spécifique à OmniRoute           |

Les trois sont indépendantes — vous pouvez en choisir n’importe quelle combinaison.

## Arbre de décision

## 1. A2A — Agent à agent

**Spécification :** [A2A v0.3](https://a2a-protocol.org)
**Point de terminaison OmniRoute :** `POST /a2a` (JSON-RPC 2.0)
**Fiche de l’agent :** `GET /.well-known/agent.json`

### Quand l’utiliser

- Créer un système multi-agent dans lequel OmniRoute est l’un des pairs
- Exposer l’intelligence de routage d’OmniRoute (`smart-routing`, `quota-management`, etc.) aux agents de frameworks tels que Google ADK ou de réseaux d’agents génériques
- Encapsuler OmniRoute derrière une interface standard de découverte et d’invocation

### Méthodes

- `message/send` — soumettre un message et recevoir une réponse synchrone
- `message/stream` — soumettre un message et recevoir des événements de progression diffusés via SSE
- `tasks/get` — lire une tâche à partir de son ID
- `tasks/cancel` — annuler une tâche en cours d’exécution

### Compétences intégrées (6)

- `smart-routing` — acheminer une requête via la combinaison optimale
- `quota-management` — indiquer l’état des quotas pour chaque fournisseur
- `provider-discovery` — répertorier les fournisseurs installés avec leurs capacités
- `cost-analysis` — estimer le coût d’une requête ou d’une conversation
- `health-report` — agréger l’état du disjoncteur, du délai de récupération et du verrouillage pour chaque fournisseur
- `list-capabilities` — énumérer les compétences disponibles de l’agent et leurs métadonnées

### Présentation détaillée

Consultez [A2A-SERVER.md](./A2A-SERVER.md) pour obtenir des détails sur le transport, la structure de la fiche de l’agent, la configuration de la durée de vie des tâches et le modèle permettant d’ajouter de nouvelles compétences.

## 2. ACP — Registre des agents CLI

**Point de terminaison OmniRoute :** `GET /api/acp/agents`
**Source :** `src/lib/acp/{index,manager,registry}.ts`

### Présentation

ACP est l’**inventaire local des agents CLI** d’OmniRoute. Il détecte les CLI de programmation installées sur l’hôte (Cursor, Cline, Claude Code, Codex CLI, Continue, etc.), détermine leurs versions et les affiche dans le tableau de bord afin que l’utilisateur puisse configurer chaque CLI pour qu’elle pointe vers OmniRoute.

L’interface HTTP est un inventaire interne qui alimente l’interface utilisateur « CLI Tools » et
le suivi des empreintes CLI (voir [CLI-TOOLS.md](../reference/CLI-TOOLS.md)). Par ailleurs,
le gestionnaire de processus interne prend en charge le protocole Agent Client Protocol natif pour le
lanceur Gemini enregistré, ainsi que les adaptateurs stdio historiques pour les autres contrats.
Consultez [le registre et les lanceurs ACP](./ACP.md) pour connaître ces différents modes et leurs limites.

### Fonctionnement

- Recherche sur l’hôte les binaires CLI installés (utilise `which` / `where` selon le système d’exploitation)
- Lit la version de chaque CLI (appelle `<bin> --version`)
- Accepte éventuellement des agents personnalisés définis par l’utilisateur (chemin du binaire + détection de la version + arguments de lancement)
- Conserve les agents personnalisés dans les paramètres
- Renvoie la liste unifiée au tableau de bord

### API REST

| Point de terminaison | Méthode | Description                                                                      | Authentification |
| -------------------- | ------- | -------------------------------------------------------------------------------- | ---------------- |
| `/api/acp/agents`    | GET     | Répertorie les agents détectés et personnalisés (nombre installés/total)         | Clé API          |
| `/api/acp/agents`    | POST    | Ajoute/met à jour/supprime un agent personnalisé (action indiquée dans le corps) | Clé API          |

Structure du corps pour POST (`customAgentBodySchema` dans `src/app/api/acp/agents/route.ts`) :

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Cas d’utilisation

- La page « CLI Tools » du tableau de bord répertorie les outils installés et vous aide à configurer chacun d’eux pour qu’il pointe vers OmniRoute
- Les agents personnalisés permettent aux utilisateurs avancés d’enregistrer des CLI internes/propriétaires qu’OmniRoute ne connaît pas par défaut
- Le résultat de la détection alimente la matrice d’empreintes `cli-tools`

### Quand NE PAS utiliser ACP

- Le registre HTTP n’accepte pas de tâches et n’expose pas le lancement de processus. Le gestionnaire
  interne peut lancer une CLI enregistrée, mais il n’est pas configuré comme solution de repli automatique
  pour les fournisseurs. Pour une utilisation interactive ordinaire, lancez vous-même la CLI configurée ou
  utilisez `omniroute run`.

## Exemples d’intégration

### Découvrir les fonctionnalités A2A d’OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

Renvoie l’Agent Card avec les 6 compétences, les transports et la version.

### Appeler OmniRoute en tant qu’agent A2A

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Répertorier les agents CLI installés via ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Ajouter un agent CLI personnalisé

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## Quel outil utiliser et dans quel cas

- **Interface de chatbot / copilote** → `/v1/chat/completions` (compatible avec OpenAI — il ne s’agit pas d’un protocole d’agent)
- **Collaboration multi-agents** → A2A
- **Affichage des CLI locales dans le tableau de bord** → ACP
- **Délégation de tâches de programmation de longue durée à des services cloud** → Cloud Agents

## Architecture interne

```
                ┌─────────────────────┐
                │   Cœur OmniRoute    │
                └─────────────────────┘
                  ↑       ↑        ↑
        ┌─────────┘       │        └─────────┐
        │                 │                  │
    ┌───────┐        ┌─────────┐       ┌────────────┐
    │  A2A  │        │   ACP   │       │  Agents   │
    │ (/a2a)│        │ (/acp)  │       │  cloud    │
    └───────┘        └─────────┘       │ (/v1/agents│
        │                 │            │  /tasks)   │
        ↓                 ↓            └────────────┘
 Agents pairs       Binaires CLI             │
 externes utilisant locaux sur               ↓
 A2A v0.3           l’hôte              Codex Cloud, Cursor,
                                        Devin, Jules
```
