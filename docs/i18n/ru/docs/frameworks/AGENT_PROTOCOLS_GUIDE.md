> **Последнее обновление:** 2026-06-28 — v3.8.40

67router предоставляет три разных интерфейса для работы с агентами. На первый взгляд они похожи, но решают разные задачи. Используйте эту страницу, чтобы выбрать подходящий вариант.

## Кратко

| Интерфейс                    | Лучше всего подходит для                                                                                                                                             | Транспорт                | Стандарт                         |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | -------------------------------- |
| **A2A — агент-агент**        | Взаимодействия между агентами, поддерживающими протокол A2A                                                                                                          | JSON-RPC 2.0 поверх HTTP | A2A v0.3 (открытая спецификация) |
| **ACP — реестр CLI-агентов** | Обнаружения, регистрации и запуска CLI-агентов для программирования, установленных на компьютере пользователя (Cursor, Cline, Codex CLI, Claude Code, Aider и т. д.) | HTTP REST                | Специфичный для 67router         |
| **Облачные агенты**          | Отправки длительных задач по программированию внешним облачным сервисам (Codex Cloud, Devin, Jules, Cursor Cloud)                                                    | HTTP REST + задачи в БД  | Специфичный для 67router         |

Эти три интерфейса независимы — используйте любое их сочетание.

## Дерево решений

## 2. ACP — реестр CLI-агентов

**Эндпоинт 67router:** `GET /api/acp/agents`
**Исходный код:** `src/lib/acp/{index,manager,registry}.ts`

### Что это такое

ACP — это **локальный реестр CLI-агентов** 67router. Он определяет, какие CLI-инструменты для написания кода установлены на хосте (Cursor, Cline, Claude Code, Codex CLI, Continue и т. д.), определяет их версии и отображает их на панели управления, чтобы пользователь мог настроить каждый CLI для работы через 67router.

HTTP-интерфейс представляет собой внутренний реестр, который обеспечивает работу интерфейса «CLI Tools» и
отслеживание отпечатков CLI (см. [CLI-TOOLS.md](../reference/CLI-TOOLS.md)). Отдельно
внутренний менеджер процессов поддерживает нативный Agent Client Protocol для
зарегистрированного средства запуска Gemini и устаревшие stdio-адаптеры для других контрактов.
Подробнее об этих отдельных режимах и ограничениях см. в разделе [Реестр ACP и средства запуска](./ACP.md).

### Что он делает

- Проверяет хост на наличие установленных исполняемых файлов CLI (использует `which` / `where` в зависимости от ОС)
- Определяет версию каждого CLI (вызывает `<bin> --version`)
- При необходимости принимает пользовательские агенты (путь к исполняемому файлу + команда проверки версии + аргументы запуска)
- Сохраняет пользовательские агенты в настройках
- Возвращает панели управления единый список

### REST API

| Эндпоинт          | Метод | Описание                                                                  | Аутентификация |
| ----------------- | ----- | ------------------------------------------------------------------------- | -------------- |
| `/api/acp/agents` | GET   | Список обнаруженных и пользовательских агентов (установлено/всего)        | API-ключ       |
| `/api/acp/agents` | POST  | Добавление/обновление/удаление пользовательского агента (действие в теле) | API-ключ       |

Структура тела запроса POST (`customAgentBodySchema` в `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Варианты использования

- Страница «CLI Tools» на панели управления показывает, что установлено, и помогает настроить каждый инструмент для работы через 67router
- Пользовательские агенты позволяют опытным пользователям регистрировать внутренние или проприетарные CLI, о которых 67router не знает по умолчанию
- Результат обнаружения используется для формирования матрицы отпечатков `cli-tools`

### Когда НЕ следует использовать ACP

- HTTP-реестр не принимает задачи и не предоставляет возможность запуска процессов. Внутренний
  менеджер может запустить зарегистрированный CLI, но не подключён в качестве автоматического резервного
  провайдера. Для обычного интерактивного использования запустите настроенный CLI самостоятельно или
  используйте `omniroute run`.

## Примеры интеграции

### Получение списка установленных CLI-агентов через ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Добавление пользовательского CLI-агента

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## Что и когда использовать

- **Фронтенд чат-бота / копилота** → `/v1/chat/completions` (совместимый с OpenAI API — не протокол агентов)
- **Мультиагентное взаимодействие** → A2A
- **Отображение локальных CLI в панели управления** → ACP
- **Делегирование длительных задач программирования облачным сервисам** → Cloud Agents
