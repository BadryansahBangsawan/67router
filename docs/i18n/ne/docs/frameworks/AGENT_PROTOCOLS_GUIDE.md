> **पछिल्लो अद्यावधिक:** 2026-06-28 — v3.8.40

67router ले एजेन्टसँग सम्बन्धित तीन फरक इन्टरफेस उपलब्ध गराउँछ। पहिलो नजरमा तिनीहरू उस्तै देखिन्छन्, तर फरक समस्याहरू समाधान गर्छन्। सही इन्टरफेस छनोट गर्न यो पृष्ठ प्रयोग गर्नुहोस्।

## छोटकरीमा

| इन्टरफेस                       | यसका लागि उत्तम                                                                                                                                   | ट्रान्सपोर्ट                    | मानक                       |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | -------------------------- |
| **A2A — एजेन्ट-देखि-एजेन्ट**   | A2A प्रोटोकल प्रयोग गर्ने सहकर्मी एजेन्टहरूसँग अन्तर-एजेन्ट सहकार्य                                                                               | HTTP मार्फत JSON-RPC 2.0        | A2A v0.3 (खुला विनिर्देशन) |
| **ACP — CLI एजेन्ट रजिस्ट्री** | प्रयोगकर्ताको मेसिनमा इन्स्टल गरिएका CLI कोडिङ एजेन्टहरू (Cursor, Cline, Codex CLI, Claude Code, Aider, आदि) पत्ता लगाउन / दर्ता गर्न / सुरु गर्न | HTTP REST                       | 67router-विशिष्ट           |
| **क्लाउड एजेन्टहरू**           | बाह्य क्लाउड सेवाहरू (Codex Cloud, Devin, Jules, Cursor Cloud) मा लामो समय चल्ने कोडिङ कार्यहरू पठाउन                                             | HTTP REST + DB-समर्थित कार्यहरू | 67router-विशिष्ट           |

यी तीनवटै स्वतन्त्र छन् — कुनै पनि उपसमूह छनोट गर्नुहोस्।

## निर्णय वृक्ष

## 2. ACP — CLI एजेन्ट रजिस्ट्री

**67router एन्डपोइन्ट:** `GET /api/acp/agents`
**स्रोत:** `src/lib/acp/{index,manager,registry}.ts`

### यो के हो

ACP भनेको 67router को **स्थानीय CLI एजेन्ट सूची** हो। यसले होस्टमा कुन-कुन कोडिङ CLI हरू इन्स्टल गरिएका छन् (Cursor, Cline, Claude Code, Codex CLI, Continue, आदि) भनेर पत्ता लगाउँछ, तिनका संस्करणहरू निर्धारण गर्छ, र प्रयोगकर्ताले प्रत्येक CLI लाई 67router तर्फ पोइन्ट गर्न सक्ने गरी ड्यासबोर्डमा देखाउँछ।

HTTP सतह एउटा आन्तरिक सूची हो जसले "CLI Tools" UI र
CLI फिङ्गरप्रिन्ट ट्र्याकिङलाई सञ्चालन गर्छ ([CLI-TOOLS.md](../reference/CLI-TOOLS.md) हेर्नुहोस्)। यसबाट अलग रूपमा,
आन्तरिक प्रक्रिया प्रबन्धकले दर्ता गरिएको Gemini लन्चरका लागि नेटिभ Agent Client Protocol र अन्य कन्ट्र्याक्टहरूका लागि पुराना stdio एडाप्टरहरू समर्थन गर्छ।
ती फरक मोड र सीमाहरूका लागि [ACP रजिस्ट्री र लन्चरहरू](./ACP.md) हेर्नुहोस्।

### यसले के गर्छ

- इन्स्टल गरिएका CLI बाइनरीहरूका लागि होस्ट जाँच गर्छ (OS अनुसार `which` / `where` प्रयोग गर्छ)
- प्रत्येक CLI को संस्करण पढ्छ (`<bin> --version` कल गर्छ)
- वैकल्पिक रूपमा प्रयोगकर्ताले परिभाषित गरेका कस्टम एजेन्टहरू स्वीकार गर्छ (बाइनरी पथ + संस्करण जाँच + स्पन आर्गुमेन्टहरू)
- कस्टम एजेन्टहरूलाई सेटिङहरूमा स्थायी रूपमा भण्डारण गर्छ
- एकीकृत सूची ड्यासबोर्डमा फर्काउँछ

### REST API

| एन्डपोइन्ट        | विधि | विवरण                                                             | प्रमाणीकरण |
| ----------------- | ---- | ----------------------------------------------------------------- | ---------- |
| `/api/acp/agents` | GET  | पत्ता लगाइएका + कस्टम एजेन्टहरूको सूची (इन्स्टल भएका/कुल सङ्ख्या) | API कुञ्जी |
| `/api/acp/agents` | POST | कस्टम एजेन्ट थप्ने/अपडेट गर्ने/हटाउने (बडीमा कार्य विभेदक)        | API कुञ्जी |

POST का लागि बडीको संरचना (`src/app/api/acp/agents/route.ts` मा `customAgentBodySchema`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### प्रयोगका अवस्थाहरू

- ड्यासबोर्डको "CLI Tools" पृष्ठले के-के इन्स्टल गरिएको छ भनेर सूचीबद्ध गर्छ र प्रत्येकलाई 67router तर्फ पोइन्ट गर्न मद्दत गर्छ
- कस्टम एजेन्टहरूले उन्नत प्रयोगकर्ताहरूलाई 67router ले पूर्वनिर्धारित रूपमा नचिन्ने आन्तरिक/स्वामित्वयुक्त CLI हरू दर्ता गर्न दिन्छन्
- पहिचानको परिणामले `cli-tools` फिङ्गरप्रिन्ट म्याट्रिक्सलाई डेटा प्रदान गर्छ

### ACP कहिले प्रयोग नगर्ने

- HTTP रजिस्ट्रीले कार्यहरू स्वीकार गर्दैन वा प्रक्रिया स्पनिङ उपलब्ध गराउँदैन। आन्तरिक
  प्रबन्धकले दर्ता गरिएको CLI सुरु गर्न सक्छ, तर यसलाई स्वचालित प्रदायक
  फलब्याकका रूपमा जोडिएको छैन। सामान्य अन्तरक्रियात्मक प्रयोगका लागि, कन्फिगर गरिएको CLI आफैँ सुरु गर्नुहोस् वा
  `omniroute run` प्रयोग गर्नुहोस्।

## एकीकरणका उदाहरणहरू

### ACP मार्फत इन्स्टल गरिएका CLI एजेन्टहरूको सूची हेर्नुहोस्

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### अनुकूलन गरिएको CLI एजेन्ट थप्नुहोस्

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## कुन अवस्थामा के प्रयोग गर्ने

- **च्याटबट / कोपाइलट फ्रन्टएन्ड** → `/v1/chat/completions` (OpenAI-सङ्गत — एजेन्ट प्रोटोकल होइन)
- **बहु-एजेन्ट सहकार्य** → A2A
- **ड्यासबोर्डमा स्थानीय CLI हरूको सूची देखाउने** → ACP
- **लामो समयसम्म चल्ने कोडिङ कार्यहरू क्लाउड सेवाहरूलाई प्रत्यायोजन गर्ने** → Cloud Agents
