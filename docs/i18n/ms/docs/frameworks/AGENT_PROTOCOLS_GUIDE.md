> **Kemas kini terakhir:** 2026-06-28 — v3.8.40

67router menyediakan tiga antara muka berkaitan ejen yang berbeza. Ketiga-tiganya kelihatan serupa pada pandangan pertama tetapi menyelesaikan masalah yang berbeza. Gunakan halaman ini untuk memilih antara muka yang sesuai.

## Ringkasan

| Antara muka               | Paling sesuai untuk                                                                                                                              | Pengangkutan                      | Piawaian                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------- | ------------------------------ |
| **A2A — Ejen-ke-Ejen**    | Kerjasama merentas ejen dengan ejen rakan setara yang menggunakan protokol A2A                                                                   | JSON-RPC 2.0 melalui HTTP         | A2A v0.3 (spesifikasi terbuka) |
| **ACP — Daftar Ejen CLI** | Mengesan / mendaftarkan / melancarkan ejen pengekodan CLI yang dipasang pada mesin pengguna (Cursor, Cline, Codex CLI, Claude Code, Aider, dll.) | HTTP REST                         | Khusus untuk 67router          |
| **Ejen Awan**             | Menghantar tugas pengekodan jangka panjang kepada perkhidmatan awan luaran (Codex Cloud, Devin, Jules, Cursor Cloud)                             | HTTP REST + tugas bersandarkan DB | Khusus untuk 67router          |

Ketiga-tiganya adalah bebas — pilih mana-mana gabungan.

## Pepohon Keputusan

## 2. ACP — Daftar Ejen CLI

**Titik akhir 67router:** `GET /api/acp/agents`
**Sumber:** `src/lib/acp/{index,manager,registry}.ts`

### Apakah itu

ACP ialah **inventori ejen CLI setempat** 67router. Ia mengesan CLI pengekodan yang dipasang pada hos (Cursor, Cline, Claude Code, Codex CLI, Continue dan sebagainya), menentukan versinya dan memaparkannya pada papan pemuka supaya pengguna boleh mengkonfigurasi setiap CLI untuk menghala ke 67router.

Antara muka HTTP ialah inventori dalaman yang menyokong UI "Alat CLI" dan
penjejakan cap jari CLI (lihat [CLI-TOOLS.md](../reference/CLI-TOOLS.md)). Secara berasingan,
pengurus proses dalaman menyokong Agent Client Protocol natif untuk pelancar
Gemini yang didaftarkan dan penyesuai stdio legasi untuk kontrak lain.
Lihat [daftar dan pelancar ACP](./ACP.md) untuk mod dan had berbeza tersebut.

### Fungsinya

- Memeriksa hos untuk mencari perduaan CLI yang dipasang (menggunakan `which` / `where` mengikut OS)
- Membaca versi setiap CLI (memanggil `<bin> --version`)
- Menerima ejen tersuai yang ditakrifkan pengguna secara pilihan (laluan perduaan + semakan versi + argumen pelancaran)
- Menyimpan ejen tersuai dalam tetapan
- Mengembalikan senarai bersepadu kepada papan pemuka

### API REST

| Titik akhir       | Kaedah | Penerangan                                                              | Pengesahan |
| ----------------- | ------ | ----------------------------------------------------------------------- | ---------- |
| `/api/acp/agents` | GET    | Senaraikan ejen yang dikesan + tersuai (bilangan dipasang/jumlah)       | Kunci API  |
| `/api/acp/agents` | POST   | Tambah/kemas kini/alih keluar ejen tersuai (pembeza tindakan dalam isi) | Kunci API  |

Bentuk isi untuk POST (`customAgentBodySchema` dalam `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Kes penggunaan

- Halaman "Alat CLI" pada papan pemuka menyenaraikan alat yang dipasang dan membantu anda menghalakan setiap satunya ke 67router
- Ejen tersuai membolehkan pengguna mahir mendaftarkan CLI dalaman/proprietari yang tidak diketahui oleh 67router secara lalai
- Hasil pengesanan membekalkan data kepada matriks cap jari `cli-tools`

### Bila ACP TIDAK patut digunakan

- Daftar HTTP tidak menerima tugasan atau menyediakan fungsi pelancaran proses. Pengurus
  dalaman boleh melancarkan CLI yang didaftarkan, tetapi tidak disambungkan sebagai sandaran
  penyedia automatik. Untuk penggunaan interaktif biasa, lancarkan sendiri CLI yang telah
  dikonfigurasi atau gunakan `omniroute run`.

## Contoh Integrasi

### Senaraikan ejen CLI yang dipasang melalui ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Tambah ejen CLI tersuai

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## Bila Perlu Menggunakan Apa

- **Antara muka chatbot / pembantu pengaturcaraan** → `/v1/chat/completions` (serasi dengan OpenAI — bukan protokol ejen)
- **Kerjasama berbilang ejen** → A2A
- **Menyenaraikan CLI setempat dalam papan pemuka** → ACP
- **Mewakilkan tugas pengekodan jangka panjang kepada perkhidmatan awan** → Ejen Awan
