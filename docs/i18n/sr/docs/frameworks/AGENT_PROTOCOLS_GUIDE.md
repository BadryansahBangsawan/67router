> **Последње ажурирање:** 2026-06-28 — v3.8.40

OmniRoute пружа три различита интерфејса повезана са агентима. На први поглед делују слично, али решавају различите проблеме. Користите ову страницу да бисте изабрали одговарајући.

## Укратко

| Интерфејс                      | Најпогодније за                                                                                                                                            | Транспорт                                  | Стандард                          |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ | --------------------------------- |
| **A2A — агент-агент**          | Сарадњу између агената са равноправним агентима који користе A2A протокол                                                                                  | JSON-RPC 2.0 преко HTTP-а                  | A2A v0.3 (отворена спецификација) |
| **ACP — регистар CLI агената** | Откривање / регистровање / покретање CLI агената за програмирање инсталираних на корисниковом рачунару (Cursor, Cline, Codex CLI, Claude Code, Aider итд.) | HTTP REST                                  | Специфично за OmniRoute           |
| **Агенти у облаку**            | Слање дуготрајних програмерских задатака спољним услугама у облаку (Codex Cloud, Devin, Jules, Cursor Cloud)                                               | HTTP REST + задаци подржани базом података | Специфично за OmniRoute           |

Ова три интерфејса су независна — изаберите било коју комбинацију.

## Стабло одлучивања

## 2. ACP — Регистар CLI агената

**OmniRoute крајња тачка:** `GET /api/acp/agents`
**Извор:** `src/lib/acp/{index,manager,registry}.ts`

### Шта је то

ACP је OmniRoute-ов **локални инвентар CLI агената**. Открива који су CLI алати за програмирање инсталирани на хосту (Cursor, Cline, Claude Code, Codex CLI, Continue итд.), утврђује њихове верзије и приказује их на контролној табли како би корисник могао да подеси сваки CLI да користи OmniRoute.

HTTP интерфејс представља интерни инвентар који покреће кориснички интерфејс „CLI Tools“ и
праћење CLI отисака (погледајте [CLI-TOOLS.md](../reference/CLI-TOOLS.md)). Засебно од тога,
интерни менаџер процеса подржава изворни Agent Client Protocol за
регистровани Gemini покретач и застареле stdio адаптере за друге уговоре.
Погледајте [ACP регистар и покретаче](./ACP.md) за информације о тим различитим режимима и ограничењима.

### Шта ради

- Проверава да ли на хосту постоје инсталиране CLI бинарне датотеке (користи `which` / `where`, у зависности од оперативног система)
- Чита верзију сваког CLI алата (позива `<bin> --version`)
- Опционо прихвата прилагођене агенте које дефинише корисник (путања до бинарне датотеке + провера верзије + аргументи за покретање)
- Трајно чува прилагођене агенте у подешавањима
- Враћа обједињену листу контролној табли

### REST API

| Крајња тачка      | Метод | Опис                                                                   | Аутентификација |
| ----------------- | ----- | ---------------------------------------------------------------------- | --------------- |
| `/api/acp/agents` | GET   | Приказује откривене + прилагођене агенте (број инсталираних/укупних)   | API кључ        |
| `/api/acp/agents` | POST  | Додаје/ажурира/уклања прилагођеног агента (дискриминатор радње у телу) | API кључ        |

Облик тела за POST (`customAgentBodySchema` у `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Случајеви употребе

- Страница „CLI Tools“ на контролној табли приказује шта је инсталирано и помаже вам да сваки алат усмерите на OmniRoute
- Прилагођени агенти омогућавају напредним корисницима да региструју интерне/власничке CLI алате које OmniRoute подразумевано не препознаје
- Резултат откривања попуњава матрицу отисака `cli-tools`

### Када НЕ треба користити ACP

- HTTP регистар не прихвата задатке нити омогућава покретање процеса. Интерни
  менаџер може да покрене регистровани CLI, али није повезан као аутоматски резервни
  добављач. За уобичајену интерактивну употребу сами покрените конфигурисани CLI или
  користите `omniroute run`.

## Примери интеграције

### Листање инсталираних CLI агената преко ACP-а

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Додавање прилагођеног CLI агента

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## Када шта користити

- **Чет-бот / копилот кориснички интерфејс** → `/v1/chat/completions` (компатибилно са OpenAI-јем — није протокол за агенте)
- **Сарадња више агената** → A2A
- **Листање локалних CLI алата на контролној табли** → ACP
- **Делегирање дуготрајних програмерских задатака услугама у облаку** → Cloud Agents
