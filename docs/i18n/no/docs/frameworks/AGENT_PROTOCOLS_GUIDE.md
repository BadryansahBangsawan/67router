> **Sist oppdatert:** 2026-06-28 — v3.8.40

67router tilbyr tre forskjellige grensesnitt relatert til agenter. Ved første øyekast ser de like ut, men de løser forskjellige problemer. Bruk denne siden til å velge det riktige.

## Kort fortalt

| Grensesnitt                        | Best egnet for                                                                                                                                   | Transport                            | Standard              |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------ | --------------------- |
| **A2A — agent-til-agent**          | Samarbeid på tvers av agenter med andre agenter som støtter A2A-protokollen                                                                      | JSON-RPC 2.0 over HTTP               | A2A v0.3 (åpen spes.) |
| **ACP — register for CLI-agenter** | Oppdaging / registrering / oppstart av CLI-kodeagenter som er installert på brukerens maskin (Cursor, Cline, Codex CLI, Claude Code, Aider osv.) | HTTP REST                            | 67router-spesifikk    |
| **Skyagenter**                     | Innsending av langvarige kodeoppgaver til eksterne skytjenester (Codex Cloud, Devin, Jules, Cursor Cloud)                                        | HTTP REST + databasebaserte oppgaver | 67router-spesifikk    |

De tre er uavhengige av hverandre — velg hvilken som helst kombinasjon.

## Beslutningstre

## 2. ACP — Register over CLI-agenter

**67router-endepunkt:** `GET /api/acp/agents`
**Kilde:** `src/lib/acp/{index,manager,registry}.ts`

### Hva det er

ACP er 67routers **lokale oversikt over CLI-agenter**. Den oppdager hvilke kode-CLI-er som er installert på verten (Cursor, Cline, Claude Code, Codex CLI, Continue osv.), finner versjonene deres og viser dem i kontrollpanelet, slik at brukeren kan konfigurere hver CLI til å peke mot 67router.

HTTP-grensesnittet er en intern oversikt som driver brukergrensesnittet «CLI Tools» og
sporing av CLI-fingeravtrykk (se [CLI-TOOLS.md](../reference/CLI-TOOLS.md)). Separat
støtter den interne prosessbehandleren den opprinnelige Agent Client Protocol for den
registrerte Gemini-starteren og eldre stdio-adaptere for andre kontrakter.
Se [ACP-register og startere](./ACP.md) for disse ulike modusene og begrensningene.

### Hva det gjør

- Søker på verten etter installerte CLI-binærfiler (bruker `which` / `where` avhengig av operativsystem)
- Leser versjonen til hver CLI (kaller `<bin> --version`)
- Godtar valgfritt egendefinerte agenter fra brukeren (bane til binærfil + versjonssjekk + startargumenter)
- Lagrer egendefinerte agenter i innstillingene
- Returnerer den samlede listen til kontrollpanelet

### REST-API

| Endepunkt         | Metode | Beskrivelse                                                          | Autentisering |
| ----------------- | ------ | -------------------------------------------------------------------- | ------------- |
| `/api/acp/agents` | GET    | Vis oppdagede og egendefinerte agenter (antall installerte/totalt)   | API-nøkkel    |
| `/api/acp/agents` | POST   | Legg til/oppdater/fjern egendefinert agent (handlingsfelt i innhold) | API-nøkkel    |

Innholdsformat for POST (`customAgentBodySchema` i `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Bruksområder

- Siden «CLI Tools» i kontrollpanelet viser hva som er installert, og hjelper deg med å konfigurere hvert verktøy til å peke mot 67router
- Egendefinerte agenter lar avanserte brukere registrere interne/proprietære CLI-er som 67router ikke kjenner til som standard
- Oppdagelsesresultatet brukes i fingeravtrykksmatrisen `cli-tools`

### Når ACP IKKE skal brukes

- HTTP-registeret tar ikke imot oppgaver eller tilbyr prosessoppstart. Den interne
  behandleren kan starte en registrert CLI, men er ikke koblet til som en automatisk
  reservetilbyder. For vanlig interaktiv bruk må du starte den konfigurerte CLI-en selv eller
  bruke `omniroute run`.

## Integrasjonseksempler

### Vis installerte CLI-agenter via ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Legg til en egendefinert CLI-agent

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## Når du bør bruke hva

- **Chatbot-/copilot-grensesnitt** → `/v1/chat/completions` (OpenAI-kompatibelt – ikke en agentprotokoll)
- **Samarbeid mellom flere agenter** → A2A
- **Visning av lokale CLI-er i kontrollpanelet** → ACP
- **Delegering av langvarige kodeoppgaver til skytjenester** → skyagenter
