67router exponerar tre olika agentrelaterade gränssnitt. De ser vid första anblicken likadana ut men löser olika problem. Använd den här sidan för att välja rätt gränssnitt.

## Kortfattat

| Gränssnitt                          | Passar bäst för                                                                                                                                           | Transport                            | Standard                       |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ------------------------------ |
| **A2A — agent till agent**          | Samarbete mellan agenter och andra agenter som använder A2A-protokollet                                                                                   | JSON-RPC 2.0 över HTTP               | A2A v0.3 (öppen specifikation) |
| **ACP — register över CLI-agenter** | Identifiering, registrering och start av CLI-kodningsagenter som är installerade på användarens dator (Cursor, Cline, Codex CLI, Claude Code, Aider osv.) | HTTP REST                            | 67router-specifik              |
| **Molnagenter**                     | Skicka långvariga kodningsuppgifter till externa molntjänster (Codex Cloud, Devin, Jules, Cursor Cloud)                                                   | HTTP REST + databaslagrade uppgifter | 67router-specifik              |

De tre är oberoende av varandra — välj valfri kombination.

## Beslutsträd

## 2. ACP — Register för CLI-agenter

**67router-slutpunkt:** `GET /api/acp/agents`
**Källa:** `src/lib/acp/{index,manager,registry}.ts`

### Vad det är

ACP är 67routers **lokala inventering av CLI-agenter**. Det identifierar vilka kodnings-CLI:er som är installerade på värden (Cursor, Cline, Claude Code, Codex CLI, Continue osv.), fastställer deras versioner och visar dem på kontrollpanelen så att användaren kan konfigurera varje CLI till att använda 67router.

HTTP-gränssnittet är ett internt register som driver användargränssnittet för "CLI Tools" och
spårning av CLI-fingeravtryck (se [CLI-TOOLS.md](../reference/CLI-TOOLS.md)). Separat
stöder den interna processhanteraren det inbyggda Agent Client Protocol för den
registrerade Gemini-startaren och äldre stdio-adaptrar för andra kontrakt.
Se [ACP-register och startare](./ACP.md) för dessa separata lägen och begränsningar.

### Vad det gör

- Söker igenom värden efter installerade CLI-binärfiler (använder `which` / `where` beroende på operativsystem)
- Läser versionen för varje CLI (anropar `<bin> --version`)
- Accepterar valfritt användardefinierade anpassade agenter (sökväg till binärfil + versionskontroll + startargument)
- Sparar anpassade agenter i inställningarna
- Returnerar den samlade listan till kontrollpanelen

### REST API

| Slutpunkt         | Metod | Beskrivning                                                           | Autentisering |
| ----------------- | ----- | --------------------------------------------------------------------- | ------------- |
| `/api/acp/agents` | GET   | Lista identifierade + anpassade agenter (antal installerade/totalt)   | API-nyckel    |
| `/api/acp/agents` | POST  | Lägg till/uppdatera/ta bort anpassad agent (åtgärdsfält i brödtexten) | API-nyckel    |

Brödtextformat för POST (`customAgentBodySchema` i `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Användningsfall

- Sidan "CLI Tools" på kontrollpanelen visar vad som är installerat och hjälper dig att konfigurera varje verktyg för 67router
- Med anpassade agenter kan avancerade användare registrera interna/proprietära CLI:er som 67router inte känner till som standard
- Identifieringsresultatet används i fingeravtrycksmatrisen `cli-tools`

### När ACP INTE ska användas

- HTTP-registret accepterar inte uppgifter och exponerar inte processstart. Den interna
  hanteraren kan starta en registrerad CLI, men är inte ansluten som en automatisk reservlösning
  för leverantörer. För vanlig interaktiv användning startar du själv den konfigurerade CLI:n eller
  använder `omniroute run`.

## Integrationsexempel

### Lista installerade CLI-agenter via ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Lägg till en anpassad CLI-agent

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## När du ska använda vad

- **Chattbot-/copilot-gränssnitt** → `/v1/chat/completions` (OpenAI-kompatibelt – inte ett agentprotokoll)
- **Samarbete mellan flera agenter** → A2A
- **Lista lokala CLI-verktyg på instrumentpanelen** → ACP
- **Delegera långvariga kodningsuppgifter till molntjänster** → Molnagenter
