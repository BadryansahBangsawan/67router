> **Zuletzt aktualisiert:** 2026-06-28 — v3.8.40

OmniRoute stellt drei verschiedene agentenbezogene Schnittstellen bereit. Auf den ersten Blick sehen sie ähnlich aus, lösen jedoch unterschiedliche Probleme. Verwenden Sie diese Seite, um die richtige auszuwählen.

## Kurzfassung

| Schnittstelle                 | Optimal für                                                                                                                                                       | Transport                         | Standard                        |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- | ------------------------------- |
| **A2A — Agent-to-Agent**      | Agentenübergreifende Zusammenarbeit mit Peer-Agenten, die das A2A-Protokoll unterstützen                                                                          | JSON-RPC 2.0 über HTTP            | A2A v0.3 (offene Spezifikation) |
| **ACP — CLI-Agentenregister** | Erkennen, Registrieren und Starten von CLI-Coding-Agenten, die auf dem Rechner des Benutzers installiert sind (Cursor, Cline, Codex CLI, Claude Code, Aider usw.) | HTTP REST                         | OmniRoute-spezifisch            |
| **Cloud-Agenten**             | Übermitteln lang laufender Coding-Aufgaben an externe Cloud-Dienste (Codex Cloud, Devin, Jules, Cursor Cloud)                                                     | HTTP REST + DB-gestützte Aufgaben | OmniRoute-spezifisch            |

Die drei Schnittstellen sind unabhängig voneinander — wählen Sie eine beliebige Kombination aus.

## Entscheidungsbaum

## 1. A2A — Agent-to-Agent

**Spezifikation:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute-Endpunkt:** `POST /a2a` (JSON-RPC 2.0)
**Agentenkarte:** `GET /.well-known/agent.json`

### Einsatzgebiete

- Aufbau eines Multi-Agenten-Systems, in dem OmniRoute einer der Peer-Agenten ist
- Bereitstellung der Routing-Intelligenz von OmniRoute (intelligentes Routing, Kontingentverwaltung usw.) für Agenten in Frameworks wie Google ADK oder generischen Agentennetzwerken
- Einbindung von OmniRoute hinter einer standardisierten Schnittstelle für Erkennung und Aufruf

### Methoden

- `message/send` — eine Nachricht übermitteln und eine synchrone Antwort empfangen
- `message/stream` — eine Nachricht übermitteln und per SSE gestreamte Fortschrittsereignisse empfangen
- `tasks/get` — eine Aufgabe anhand ihrer ID abrufen
- `tasks/cancel` — eine laufende Aufgabe abbrechen

### Integrierte Fähigkeiten (6)

- `smart-routing` — einen Prompt über die optimale Kombination routen
- `quota-management` — den Kontingentstatus für jeden Anbieter melden
- `provider-discovery` — installierte Anbieter mit ihren Funktionen auflisten
- `cost-analysis` — die Kosten einer Anfrage oder Unterhaltung schätzen
- `health-report` — den Status von Schutzschaltern, Abklingzeiten und Sperren für jeden Anbieter aggregieren
- `list-capabilities` — die verfügbaren Fähigkeiten und Metadaten des Agenten auflisten

### Vertiefung

Weitere Informationen zu Transportdetails, zur Struktur der Agentenkarte, zur TTL-Konfiguration von Aufgaben und zur Vorlage für das Hinzufügen neuer Fähigkeiten finden Sie unter [A2A-SERVER.md](./A2A-SERVER.md).

## 2. ACP — CLI-Agentenregister

**OmniRoute-Endpunkt:** `GET /api/acp/agents`
**Quelle:** `src/lib/acp/{index,manager,registry}.ts`

### Was es ist

ACP ist OmniRoutes **lokales Verzeichnis für CLI-Agenten**. Es erkennt, welche Coding-CLIs auf dem Host installiert sind (Cursor, Cline, Claude Code, Codex CLI, Continue usw.), ermittelt deren Versionen und stellt sie dem Dashboard bereit, damit Benutzer jede CLI so konfigurieren können, dass sie auf OmniRoute verweist.

Die HTTP-Schnittstelle ist ein internes Verzeichnis, das die Benutzeroberfläche „CLI Tools“ und
die Verfolgung von CLI-Fingerprints ermöglicht (siehe [CLI-TOOLS.md](../reference/CLI-TOOLS.md)). Unabhängig davon
unterstützt der interne Prozessmanager das native Agent Client Protocol für den
registrierten Gemini-Launcher sowie ältere stdio-Adapter für andere Schnittstellen.
Weitere Informationen zu diesen unterschiedlichen Modi und Einschränkungen finden Sie unter [ACP-Register und -Launcher](./ACP.md).

### Funktionsweise

- Prüft den Host auf installierte CLI-Binärdateien (verwendet je nach Betriebssystem `which` / `where`)
- Liest die Version jeder CLI aus (ruft `<bin> --version` auf)
- Akzeptiert optional benutzerdefinierte Agenten (Binärdateipfad + Versionsabfrage + Startargumente)
- Speichert benutzerdefinierte Agenten in den Einstellungen
- Gibt die vereinheitlichte Liste an das Dashboard zurück

### REST-API

| Endpunkt          | Methode | Beschreibung                                                                            | Authentifizierung |
| ----------------- | ------- | --------------------------------------------------------------------------------------- | ----------------- |
| `/api/acp/agents` | GET     | Erkannte + benutzerdefinierte Agenten auflisten (installiert/gesamt)                    | API-Schlüssel     |
| `/api/acp/agents` | POST    | Benutzerdefinierten Agenten hinzufügen/aktualisieren/entfernen (Aktionskennung im Body) | API-Schlüssel     |

Body-Struktur für POST (`customAgentBodySchema` in `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Anwendungsfälle

- Die Dashboard-Seite „CLI Tools“ zeigt an, was installiert ist, und hilft Ihnen dabei, jede CLI auf OmniRoute auszurichten
- Mit benutzerdefinierten Agenten können erfahrene Benutzer interne/proprietäre CLIs registrieren, die OmniRoute standardmäßig nicht kennt
- Das Erkennungsergebnis speist die `cli-tools`-Fingerprint-Matrix

### Wann ACP NICHT verwendet werden sollte

- Das HTTP-Register nimmt keine Aufgaben an und bietet keine Prozessstartfunktion. Der interne
  Manager kann eine registrierte CLI starten, ist jedoch nicht als automatischer Provider-
  Fallback eingebunden. Starten Sie für die gewöhnliche interaktive Nutzung die konfigurierte CLI selbst oder
  verwenden Sie `omniroute run`.

## Integrationsbeispiele

### A2A-Funktionen von OmniRoute ermitteln

```bash
curl http://localhost:20128/.well-known/agent.json
```

Gibt die Agent Card mit allen 6 Fähigkeiten, Transporten und der Version zurück.

### OmniRoute als A2A-Agent aufrufen

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Installierte CLI-Agenten über ACP auflisten

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Einen benutzerdefinierten CLI-Agenten hinzufügen

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## Wann was verwendet werden sollte

- **Chatbot-/Copilot-Frontend** → `/v1/chat/completions` (OpenAI-kompatibel – kein Agentenprotokoll)
- **Zusammenarbeit mehrerer Agenten** → A2A
- **Lokale CLIs im Dashboard auflisten** → ACP
- **Lang laufende Programmieraufgaben an Cloud-Dienste delegieren** → Cloud Agents

## Interne Architektur

```
                ┌─────────────────────┐
                │   OmniRoute Core    │
                └─────────────────────┘
                  ↑       ↑        ↑
        ┌─────────┘       │        └─────────┐
        │                 │                  │
    ┌───────┐        ┌─────────┐       ┌────────────┐
    │  A2A  │        │   ACP   │       │  Cloud-    │
    │ (/a2a)│        │ (/acp)  │       │  Agenten   │
    └───────┘        └─────────┘       │ (/v1/agents│
        │                 │            │  /tasks)   │
        ↓                 ↓            └────────────┘
   Externe Peer-     Lokale CLI-             │
   Agenten, die      Binärdateien auf         ↓
   A2A v0.3          dem Host           Codex Cloud, Cursor,
   unterstützen                         Devin, Jules
```
