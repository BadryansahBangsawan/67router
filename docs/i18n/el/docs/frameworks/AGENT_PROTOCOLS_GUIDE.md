> **Τελευταία ενημέρωση:** 2026-06-28 — v3.8.40

Το OmniRoute διαθέτει τρεις διαφορετικές επιφάνειες που σχετίζονται με agents. Με την πρώτη ματιά μοιάζουν, αλλά επιλύουν διαφορετικά προβλήματα. Χρησιμοποιήστε αυτήν τη σελίδα για να επιλέξετε την κατάλληλη.

## Εν συντομία

| Επιφάνεια                   | Ιδανική για                                                                                                                                                           | Μεταφορά                                | Πρότυπο                        |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- | ------------------------------ |
| **A2A — Agent-to-Agent**    | Συνεργασία μεταξύ agents με ομότιμους agents που υποστηρίζουν το πρωτόκολλο A2A                                                                                       | JSON-RPC 2.0 μέσω HTTP                  | A2A v0.3 (ανοικτή προδιαγραφή) |
| **ACP — Μητρώο CLI Agents** | Εντοπισμό / καταχώριση / εκκίνηση CLI agents προγραμματισμού που είναι εγκατεστημένοι στον υπολογιστή του χρήστη (Cursor, Cline, Codex CLI, Claude Code, Aider κ.λπ.) | HTTP REST                               | Ειδικό για το OmniRoute        |
| **Cloud Agents**            | Υποβολή μακροχρόνιων εργασιών προγραμματισμού σε εξωτερικές υπηρεσίες cloud (Codex Cloud, Devin, Jules, Cursor Cloud)                                                 | HTTP REST + εργασίες στη βάση δεδομένων | Ειδικό για το OmniRoute        |

Οι τρεις επιφάνειες είναι ανεξάρτητες — επιλέξτε οποιοδήποτε υποσύνολο.

## Δέντρο αποφάσεων

## 1. A2A — Agent-to-Agent

**Προδιαγραφή:** [A2A v0.3](https://a2a-protocol.org)
**Τερματικό σημείο OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**Κάρτα Agent:** `GET /.well-known/agent.json`

### Πότε να το χρησιμοποιήσετε

- Κατά τη δημιουργία ενός συστήματος πολλαπλών agents, όπου το OmniRoute είναι ένας από τους ομότιμους κόμβους
- Για τη διάθεση της ευφυΐας δρομολόγησης του OmniRoute (έξυπνη δρομολόγηση, διαχείριση ορίων χρήσης κ.λπ.) σε agents που λειτουργούν σε πλαίσια όπως το Google ADK ή σε γενικά δίκτυα agents
- Για την ενσωμάτωση του OmniRoute πίσω από μια τυποποιημένη επιφάνεια εντοπισμού + επίκλησης

### Μέθοδοι

- `message/send` — υποβάλλει ένα μήνυμα και λαμβάνει συγχρονισμένη απόκριση
- `message/stream` — υποβάλλει ένα μήνυμα και λαμβάνει συμβάντα προόδου μέσω ροής SSE
- `tasks/get` — διαβάζει μια εργασία βάσει ID
- `tasks/cancel` — ακυρώνει μια εργασία που εκτελείται

### Ενσωματωμένες δεξιότητες (6)

- `smart-routing` — δρομολογεί μια προτροπή μέσω του βέλτιστου συνδυασμού
- `quota-management` — αναφέρει την κατάσταση των ορίων χρήσης ανά πάροχο
- `provider-discovery` — παραθέτει τους εγκατεστημένους παρόχους και τις δυνατότητές τους
- `cost-analysis` — εκτιμά το κόστος ενός αιτήματος/μιας συνομιλίας
- `health-report` — συγκεντρώνει την κατάσταση breaker/cooldown/lockout ανά πάροχο
- `list-capabilities` — απαριθμεί τις διαθέσιμες δεξιότητες και τα μεταδεδομένα του agent

### Αναλυτικές πληροφορίες

Ανατρέξτε στο [A2A-SERVER.md](./A2A-SERVER.md) για λεπτομέρειες σχετικά με τη μεταφορά, τη δομή της κάρτας agent, τη διαμόρφωση TTL των εργασιών και το πρότυπο για την προσθήκη νέων δεξιοτήτων.

## 2. ACP — Μητρώο CLI Agents

**Endpoint του OmniRoute:** `GET /api/acp/agents`
**Πηγή:** `src/lib/acp/{index,manager,registry}.ts`

### Τι είναι

Το ACP είναι το **τοπικό ευρετήριο CLI agents** του OmniRoute. Εντοπίζει ποια CLI προγραμματισμού είναι εγκατεστημένα στον κεντρικό υπολογιστή (Cursor, Cline, Claude Code, Codex CLI, Continue κ.λπ.), προσδιορίζει τις εκδόσεις τους και τα εμφανίζει στον πίνακα ελέγχου, ώστε ο χρήστης να μπορεί να ρυθμίσει κάθε CLI να παραπέμπει στο OmniRoute.

Η διεπαφή HTTP αποτελεί ένα εσωτερικό ευρετήριο που υποστηρίζει το UI «CLI Tools» και την παρακολούθηση αποτυπωμάτων CLI (βλ. [CLI-TOOLS.md](../reference/CLI-TOOLS.md)). Ξεχωριστά, ο εσωτερικός διαχειριστής διεργασιών υποστηρίζει το εγγενές Agent Client Protocol για τον καταχωρισμένο εκκινητή Gemini και παλαιού τύπου προσαρμογείς stdio για άλλες συμβάσεις. Ανατρέξτε στο [Μητρώο ACP και εκκινητές](./ACP.md) για αυτούς τους διακριτούς τρόπους λειτουργίας και τους περιορισμούς τους.

### Τι κάνει

- Ελέγχει τον κεντρικό υπολογιστή για εγκατεστημένα εκτελέσιμα CLI (χρησιμοποιεί `which` / `where` ανά λειτουργικό σύστημα)
- Διαβάζει την έκδοση κάθε CLI (καλεί `<bin> --version`)
- Προαιρετικά δέχεται προσαρμοσμένους agents που ορίζει ο χρήστης (διαδρομή εκτελέσιμου + έλεγχος έκδοσης + ορίσματα εκκίνησης)
- Αποθηκεύει μόνιμα τους προσαρμοσμένους agents στις ρυθμίσεις
- Επιστρέφει την ενοποιημένη λίστα στον πίνακα ελέγχου

### REST API

| Endpoint          | Μέθοδος | Περιγραφή                                                                               | Έλεγχος ταυτότητας |
| ----------------- | ------- | --------------------------------------------------------------------------------------- | ------------------ |
| `/api/acp/agents` | GET     | Παραθέτει τους εντοπισμένους + προσαρμοσμένους agents (πλήθος εγκατεστημένων/συνολικών) | Κλειδί API         |
| `/api/acp/agents` | POST    | Προσθέτει/ενημερώνει/καταργεί προσαρμοσμένο agent (διακριτικό ενέργειας στο σώμα)       | Κλειδί API         |

Μορφή σώματος για POST (`customAgentBodySchema` στο `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Περιπτώσεις χρήσης

- Η σελίδα «CLI Tools» του πίνακα ελέγχου παραθέτει όσα είναι εγκατεστημένα και σας βοηθά να ρυθμίσετε το καθένα ώστε να παραπέμπει στο OmniRoute
- Οι προσαρμοσμένοι agents επιτρέπουν σε προχωρημένους χρήστες να καταχωρίζουν εσωτερικά/ιδιόκτητα CLI που το OmniRoute δεν γνωρίζει από προεπιλογή
- Το αποτέλεσμα του εντοπισμού τροφοδοτεί τον πίνακα αποτυπωμάτων `cli-tools`

### Πότε να ΜΗ χρησιμοποιείτε το ACP

- Το μητρώο HTTP δεν δέχεται εργασίες ούτε εκθέτει τη δημιουργία διεργασιών. Ο εσωτερικός διαχειριστής μπορεί να εκκινήσει ένα καταχωρισμένο CLI, αλλά δεν είναι συνδεδεμένος ως αυτόματη εναλλακτική λύση παρόχου. Για συνήθη διαδραστική χρήση, εκκινήστε μόνοι σας το ρυθμισμένο CLI ή χρησιμοποιήστε `omniroute run`.

## Παραδείγματα ενσωμάτωσης

### Ανακάλυψη των δυνατοτήτων A2A του OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

Επιστρέφει την Κάρτα Agent με όλες τις 6 δεξιότητες, τους τρόπους μεταφοράς και την έκδοση.

### Κλήση του OmniRoute ως A2A agent

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Εμφάνιση των εγκατεστημένων CLI agents μέσω ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Προσθήκη προσαρμοσμένου CLI agent

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

## Πότε να χρησιμοποιείτε τι

- **Frontend chatbot / copilot** → `/v1/chat/completions` (συμβατό με OpenAI — δεν αποτελεί πρωτόκολλο agent)
- **Συνεργασία πολλαπλών agents** → A2A
- **Εμφάνιση τοπικών CLI στον πίνακα ελέγχου** → ACP
- **Ανάθεση εργασιών προγραμματισμού μεγάλης διάρκειας σε υπηρεσίες cloud** → Cloud Agents
